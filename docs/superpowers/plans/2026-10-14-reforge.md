# Reforge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players spend drop materials and yen at a smith NPC to level up (to 10) and reroll the two modifier slots of any weapon or power they own.

**Architecture:** Reforge state is per skill set, saved as one text field. All rules live in a pure, Lune-tested module (`ReforgeRules`) over numbers in `ReforgeConfig`. A server module `Reforge` holds state and runs the checked actions; combat reads it in two existing places (damage multiplier in `Damage.Deal`, cooldown in `SkillSetServer`), and status procs plus lifesteal run from a `Damage.OnDealt` listener so `Damage` never requires `StatusEffects` (that would be a require cycle).

**Tech Stack:** Roblox Luau, Lune for pure-module tests (`tests/run.sh`).

**Spec:** `docs/superpowers/specs/2026-10-14-reforge-design.md`. Materials come from `docs/superpowers/specs/2026-10-14-enemy-drops-design.md`.

**Worktree/branch:** `../somewhat-rpg-reforge`, branch `reforge` (from `enemy-drops`).

## Global Constraints

- UI is square: no `UICorner` anywhere.
- All player damage goes through `Damage.Deal`; the reforge multiplier is applied inside it. Nothing else changes damage.
- Max level 10, +4% damage per level; slots unlock at levels 3 and 7; reforge bonus halved against players; `ProcCooldown = 1` s per victim per status; `options.dot` ticks never get a bonus or proc anything.
- Modifier values are integers in tenths of a percent (`55` = 5.5%). Ranges: Might 30-100, Swift 30-100, Searing/Rending/Venom/Sapping 80-200, Vampiric 20-60.
- Costs (placeholders, in `ReforgeConfig`): levels 1-3 Scrap 10/15/20 + ¥200 each; 4-6 Core 5/8/12 + ¥1000; 7-9 Crystal 3/5/8 + ¥5000; 10 Essence 3 + ¥20000. Reroll: slot 1 = 3 Core + ¥500, slot 2 = 3 Crystal + ¥2500.
- Leveling never fails or loses a level. A reroll is paid when rolled; Keep / Take old after that is free.
- Server owns every check: owner of the set, within `Range = 14` studs (+4 tolerance, like `ShopServer`) of a living `Smith` model, materials and yen present, rate limit, argument types.
- Saved text field `Reforge`, max length 400. Format: sets joined by `;`, each `Set=level:slot1,slot2`, a slot is `id=value` or `-`. Example: `Revolver=7:Might=55,-;Mandela=3:Vampiric=40,-`.
- Match surrounding code: comment style, `make()`-style UI helpers from `ShopMenu`, attributes for client-visible state.
- Tests need Lune (`cargo install lune`); `tests/run.sh` runs all of them. The game parts can only be checked in Studio.
- Prerequisite for tasks 2+: the enemy-drops implementation provides the saved `Mat_<key>` attributes (keys `Scrap`, `Core`, `Crystal`, `Essence`). Tasks 1 can run first.

## Review Focus

- A corrupt or hand-edited `Reforge` string (unknown set, level 99, unknown modifier, value out of range, duplicate modifier, modifier in a locked slot): `Decode` clamps or drops it and never errors (Task 1).
- Two rapid level-up requests with exactly enough materials for one: only one goes through, nothing goes negative (Task 3).
- Reroll with a pending candidate already waiting, then leaving or a second reroll: only the latest candidate can be resolved, and `keep` with none pending is refused (Task 3).
- A set the player doesn't own, or the Fists, sent to the remote: refused with a message, no spend (Task 3, 4).
- Multi-hit skills and damage-over-time ticks with Searing/Rending/Venom/Sapping/Vampiric: at most one proc per second per victim per status, none from ticks (Task 5).

### Task 1: Config and pure rules

**Files:**
- Create: `src/ReplicatedStorage/ReforgeConfig.luau`, `src/ReplicatedStorage/ReforgeRules.luau`
- Test: `tests/ReforgeRules.spec.luau` (same `check(name, condition)` style as `tests/DayCycleConfig.spec.luau`)

**Interfaces:**
- Produces, `ReforgeConfig`: `MaxLevel`, `DamagePerLevel`, `SlotUnlockLevels = {3, 7}`, `PvPFactor`, `ProcCooldown`, `Range`, `Tag = "Smith"`, `Remote = "ReforgeAction"`, `Attribute = "Reforge"`, `SetAttribute(setName) -> "Reforge_" .. setName`, `LevelCosts[level] = { material, amount, yen }` (levels 1-10), `RerollCosts[slot] = { material, amount, yen }`, `Modifiers` (ordered list of `{ id, name, kind = "damage"|"cooldown"|"status"|"lifesteal", status = "Burnt"|"Bleeding"|"Poisoned"|"Weakened"?, min, max }`), `ReforgeConfig.Modifier(id) -> table?`.
- Produces, `ReforgeRules` (no Roblox services; takes `random` as a `(lo, hi) -> integer` argument like `math.random`):
  - `type State = { level: number, mods: { [number]: { id: string, value: number } } }` (mods keyed by slot 1-2, may be sparse)
  - `NewState() -> State`; `SlotsUnlocked(level) -> number`
  - `PlanLevelUp(state, bag: {[string]: number}, yen: number) -> (true, cost) | (false, reason: string)`
  - `PlanReroll(state, slot, bag, yen) -> (true, cost) | (false, reason)` (slot must be 1-2 and unlocked)
  - `Roll(random, taken: {[string]: boolean}) -> { id, value }` (uniform among modifiers not taken, value uniform in its range)
  - `DamageMultiplier(state, vsPlayer: boolean) -> number`; `CooldownMultiplier(state) -> number`; `StatusChance(state, status) -> number` (0-1); `Lifesteal(state) -> number` (0-1)
  - `EncodeState(state) -> string` (`level:slot1,slot2`), `DecodeState(text) -> State` (clamps/drops bad parts, never errors); `Encode(states: {[string]: State}) -> string`, `Decode(text, isSet: (string) -> boolean) -> {[string]: State}` (drops unknown sets, skips empty level-0 states in `Encode`)

### Task 3: Actions (level up, reroll, resolve)

**Files:**

**Interfaces:**

- Produces on `Reforge`: `Reforge.LevelUp(player, setName) -> ok: boolean, message: string`; `Reforge.Reroll(player, setName, slot) -> ok, message, candidate?` with `candidate = { slot, old = { id, value }?, new = { id, value } }`; `Reforge.Resolve(player, setName, keep) -> ok, message`; `Reforge.ClearPending(player)`.
- Produces: the server handler for `ReplicatedStorage.ReforgeAction` (`OnServerInvoke(player, action, setName, arg)` with `action` `"level" | "reroll" | "resolve"`).

- [ ] **Step 1: Implement the three actions in `Reforge`.** Shared validation first: `typeof(setName) == "string"`, set exists, `Loadout.Owns(player, setName)`; then `PlanLevelUp`/`PlanReroll` with the player's `Mat_<key>` attributes as the bag and `Yen`; spend with no yields in between (yen via `PlayerStats.SpendYen`, then `SetAttribute("Mat_"..key, current - amount)` for the material); then write the new `Reforge` string with `ReforgeRules.Encode`. `LevelUp` increments the level. `Reroll` pays, calls `ReforgeRules.Roll(math.random, taken)` where `taken` is the other slot's id, and stores the candidate in a per-player pending table (a new reroll for the same set replaces it). `Resolve(keep=true)` writes `candidate.new` into the slot; `false` discards. - [ ] **Step 2: Implement `ReforgeServer.server.luau`**: gets `ReforgeAction` with `WaitForChild`, `OnServerInvoke` validates `action` is one of the three strings, enforces a 0.3 s per-player interval (same shape as `Loadout`'s `lastEquip`), requires a living `Smith`-tagged `Model` within `ReforgeConfig.Range + 4` studs of the character root (copy `nearShop`'s shape from `ShopServer.server.luau`), then calls the matching `Reforge` function and returns `ok, message, candidate`. Calls `Reforge.Start()`.
