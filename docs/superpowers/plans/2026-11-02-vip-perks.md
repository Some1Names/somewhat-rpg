# VIP perks (plan only, nothing built yet)

Written 2026-11-02. Status: **not started**, waiting for the owner's go. Branch
`claude/vigilant-rubin-ckqtnn`. Related: slot 3 is Robux-only (`SlotConfig.RobuxSlots`), and the VIP is
a separate perk, so slot 3 stays locked for VIPs too.

## Goal

A VIP game pass with convenience and cosmetic perks, none of them combat power (no damage, HP or
skill changes), so it is not pay-to-win.

## Perks (the bundle)

1. **VIP tee and title.** The `VIP` tee already exists in `SlotConfig.TeeStyles`; only VIPs can pick
   it. A gold "VIP" tag shows in `OverheadHealth` (under the name, beside the faction title) and in
   the `Leaderboard` row.
2. **+25% XP and yen** from earned rewards (kills, quests, drops). Not from selling, refunds or
   admin grants. The pickup feed shows the boosted number.
3. **Fast travel cooldown halved** (10 s to 5 s, `FastTravelConfig.Cooldown`).
4. **A 3rd power storage slot** (`PowerConfig.StorageSlots` is 2; VIP gets 3).
5. **Free recustomize** of a character's look (the customizer's SAVE on an existing slot).

## Design

- **`VipConfig`** (`ReplicatedStorage`, pure, Lune-tested in `tests/VipConfig.spec.luau`):
  `PassId = 0` (0 = not made yet, so nobody is VIP), `XpYenMultiplier = 1.25`,
  `TravelCooldownScale = 0.5`, `ExtraStorageSlots = 1`, `Title = "VIP"`, `TitleColor` (gold).
  Pure rules: `Multiplier(isVip, kind)`, `TravelCooldown(base, isVip)`,
  `StorageSlots(base, isVip)`, `CanUseTee(isVip, teeName)`.
- **`Vip`** (`ServerScriptService` module + small script): on join, asks
  `MarketplaceService:UserOwnsGamePassAsync` (retries, `pcall`) and sets the player attribute `Vip`
  (true/false). Listens to `PromptGamePassPurchaseFinished` so buying mid-session turns it on
  at once. `Vip.Is(player)` is the one check everything else uses. Account-level, not per slot.
  Studio can't verify ownership, so an admin/Studio override (an attribute or a `DebugVip` flag in
  `VipConfig`) is needed for testing.
- **XP/yen:** `PlayerStats.AddXP` / `AddYen` take the `source` from `PlayerStats.Source`. Add an
  opt-out rather than boosting everything: the boost applies unless the source's tier is `Admin`, or
  a new `noBoost` field on the source is set (sells and refunds pass it). Check every
  `AddYen` caller (`ShopServer`, `Powers` sells, `Quests`, `Drops`) before turning it on.
- **Fast travel:** `FastTravelServer` uses `FastTravelConfig.CooldownLeft`; pass the scaled cooldown
  for a VIP. The client's cooldown display reads the `cooldown` the server sends, so it follows.
- **Storage:** `Powers.lua` reads `PowerConfig.StorageSlots` in several places (free slots,
  pick-up, sell, UI count); replace with `PowerConfig.SlotsFor(isVip)` and make sure a power
  already in slot 3 is kept (never deleted) if VIP is lost.
- **Tee:** the customizer hides `VIP` for non-VIPs (client reads the `Vip` attribute);
  `Slots.Create` / `Slots.Recustomize` reject a look that uses it (server is the real check). A
  character already wearing it keeps wearing it.
- **Recustomize:** `Slots.Recustomize` is already free; the plan is to confirm whether it should be
  VIP-only. Open question below.
- **Tag:** `Vip` attribute drives a `TextLabel` in `OverheadHealth` and `Leaderboard` (white with a
  dark stroke per the top-of-screen UI rule, gold text for the VIP tag). Square UI, no `UICorner`.
- **Purchase prompt:** a VIP entry in the hub (Profile card) with a BUY button that calls
  `MarketplaceService:PromptGamePassPurchase`; hidden or "coming soon" while `PassId == 0`.
