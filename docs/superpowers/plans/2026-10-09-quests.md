# Quests (Level Quests and Mastery Challenges) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Who runs it:** Tasks 1–6 are code only: a **cloud session** can do them. Task 7 needs
> **Studio and the owner** (real quests, givers, `EnemyType` attributes). Branch
> `claude/vigilant-rubin-ckqtnn` (or a fresh branch off it). Read `CLAUDE.md`.

**Goal:** Repeatable level quests from NPC givers ("Defeat 6 Bandits", one at a time, paid on the spot at 1.5× the kills) and saved, once-only mastery challenges per set, with a tracker and a Quests menu on J.

**Architecture:** Data and pure helpers in `QuestConfig` (Lune-tested); move tags (`options.skill`) in every skill's damage options so hits and kills know their move; a `Quests` module plus `QuestServer` script that tracks level quests (session) and challenges (saved as a `PlayerStats` text field) from `Damage.OnDealt`, the kill payout and `Quests.Report` events; client scripts for the giver panel, tracker and menu.

**Tech Stack:** Roblox Luau; Lune (`tests/run.sh`); StyLua (parse) and selene in `~/.cargo/bin`.

**Spec:** `docs/superpowers/specs/2026-10-09-quests-design.md` (the challenge table, rewards, every rule).

## Global Constraints

- Quest and challenge data live only in `QuestConfig`. `RewardShare = 1.5`.
- XP, yen and mastery only through `PlayerStats` (`AddXP`, `AddYen`, `AddMasteryXP`).
- Studio-only instances (givers tagged `QuestGiver` with `GiverId`, the `EnemyType` attribute on enemies) are listed for Task 7, never assumed present: no givers means no panel, and nothing errors.
- UI square (no `UICorner`), in the style of Inventory/StatsMenu; J is a fixed menu key and is removed from `Keybinds.Allowed`.
- Match the surrounding style (header comments, tabs, existing helpers).

## Review Focus

1. **Kill credit for quests:** a quest kill counts only for the player who gets the NPC payout (`Damage`'s `payOutOnDeath`), once per death, and only when `EnemyType` matches. (Task 3 step.)
2. **Saved progress limits:** the `Challenges` text stays under its 1,000-character limit with every set's challenges; a corrupt or too-long saved value loads as empty instead of erroring. (Task 1 test + Task 3 step.)
3. **Done stays done:** a completed challenge never pays twice (rejoin, a second event in the same frame). (Task 1 test.)
4. **Untagged moves:** a damage call left without `skill` simply doesn't count for `hits`/`kills` challenges (no error). (Task 2 step.)
5. **Giver panel abuse:** the server re-checks the player's level and that they're near that giver before accepting. (Task 3 step.)
