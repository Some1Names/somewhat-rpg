# Crafting (3D printer) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 3D printer where players spend materials and yen to start timed prints that make gear pieces or talismans, with some recipes known from the start and the rest learned.

**Architecture:** `CraftConfig` (pure, Lune-tested) holds recipes and every rule; `Crafting` (server module) applies them to the player's materials, yen and saved texts; `CraftServer` is the remote; `PrinterMenu` is the client menu. Same shape as `TalismanConfig`/`Talismans` and `ReforgeConfig`/`Reforge`.

**Tech Stack:** Luau (Roblox), Lune for tests (`tests/run.sh`), Studio for the smoke test.

**Spec:** `docs/superpowers/specs/2026-11-03-crafting-design.md`

## Global Constraints

- UI is square: no `UICorner` anywhere in `PrinterMenu`.
- Materials are the player attributes `Mat_<key>` (`DropConfig.Attribute(key)`), capped at `DropConfig.MaxPerMaterial` (999). Yen is the player's `Yen` attribute (check `PlayerStats` for the exact name before use).
- Saved text attributes are registered in `PlayerStats` `TEXT_DEFAULTS` and `TEXT_LENGTHS`: `PrintJobs`, `RecipesKnown`.
- Pure modules take no Roblox types (Lune must `require` them); server modules do the Roblox work.
- Match surrounding code: comment density, tabs, naming. No final VFX (the owner's).
- Studio is the source of truth: new files are applied to Studio by a local session afterwards (CLAUDE.md "Syncing with Studio"); list new instances needed.
- `TalismanConfig.OwnAll = true` today, so talisman recipes only matter when it is off; tests set `OwnAll = false`.
- `Gear` (equipment spec) may not exist yet: gear recipes must be disabled, not crash, until `ServerScriptService.Gear` with `Gear.Grant(player, slot, rarity, level, seed, affixHint) -> ok, why` exists.

## Review Focus

- Rejoining or reconnecting mid-print must not reroll the result or restart the timer (seed + `finishAt` are saved).
- Starting a print with exactly enough materials, or one short, must charge all or nothing.
- Two rapid `Start` calls (double click) must not spend twice or use a second job slot.
- A bad or tampered `PrintJobs`/`RecipesKnown` text (junk entries, unknown recipes, negative times) must parse to a safe list, not error.
- A learned recipe's blueprint/yen must be spent only when learning succeeds, and learning twice must be refused.

### Task 1: CraftConfig (pure rules)

**Files:**
- Create: `src/ReplicatedStorage/CraftConfig.luau`
- Test: `tests/CraftConfig.spec.luau`

**Interfaces:**
- Produces (all on the `CraftConfig` table):
  - fields: `Tag = "Printer"`, `Range = 14`, `Remote = "CraftAction"`, `JobsAttribute = "PrintJobs"`, `KnownAttribute = "RecipesKnown"`, `MaxSaveLength = 400`, `JobSlotLevels = { 0, 20, 50 }`, `CancelRefund = 0.5`, `Recipes` (list).
  - `Get(id: string): Recipe?`
  - `ParseJobs(text: any): { Job }` where `Job = { recipe: string, seed: number, finishAt: number }`; drops unknown recipes and junk; `EncodeJobs(jobs): string` (`recipe|seed|finishAt;...`).
  - `ParseKnown(text: any): { string }` (valid learnable ids, once each); `EncodeKnown(list): string`.
  - `IsKnown(knownText: any, id: string): boolean` (`access == "known"` or listed).
  - `JobSlots(level: number): number`, `NextSlotLevel(level: number): number?`.
  - `CanAfford(recipe, material: (key: string) -> number, yen: number): boolean`.
  - `Start(knownText, jobsText, id, level, now, seed): (string?, string?)` returns new jobs text or nil + why ("Unknown recipe", "Recipe not learned", "No free print slot").
  - `IsReady(job: Job, now: number): boolean`.
  - `Remove(jobsText, index): (string?, Job?)` removes job `index`, returns new text and the job.
  - `Refund(recipe): { {material: string, amount: number} }` (`floor(amount * CancelRefund)`, drops zero amounts).
  - `Learn(knownText, id, routeKind): (string?, string?)` new known text or nil + why ("Unknown recipe", "Already known", "Can't be learned that way").
  - `RollRarity(weights: { [string]: number }, random: () -> number): string`.
  - `Recipe = { id, name, tier, materials = {{material, amount}}, yen, seconds, output = {kind, slot?, key?}, access, routes?, rarityWeights?, affix?, maxLevel? }`.

- [ ] **Step 1: Write the failing test** `tests/CraftConfig.spec.luau`, in the style of `tests/TalismanConfig.spec.luau` (its `check`/`failures` helpers, `os.exit(failures)` at the end). Assertions, using the real starter recipes:
  - every recipe has a unique `id`, a positive `seconds`, non-empty `materials`, and `output.kind` in `gear`/`talisman`; a `learn` recipe has a `routes` table.
  - `JobSlots(1) == 1`, `JobSlots(20) == 2`, `JobSlots(50) == 3`; `NextSlotLevel(50) == nil`.
  - `ParseJobs("RoughHelm|5|100;Nope|1|1;RoughHelm|x|y;;RoughHelm|-3|-9")` keeps only the valid first entry; round trip with `EncodeJobs`.
  - `Start` with 1 slot and 1 job already: returns `nil, "No free print slot"`; with a `learn` recipe not in `RecipesKnown`: `nil, "Recipe not learned"`; success appends `id|seed|now+seconds`.
  - `CanAfford` true at exactly enough, false at one material short and at one yen short.
  - `IsReady({finishAt = 100}, 99) == false`, `IsReady(..., 100) == true`.
  - `Remove` out of range returns nil; in range returns the job and the shorter text.
  - `Refund` of a recipe with `amount = 1` returns an empty list; with `amount = 15` returns 7.
  - `Learn` twice returns nil, "Already known" the second time; a recipe without that route kind returns "Can't be learned that way"; a `known` recipe returns "Already known".
  - `RollRarity({Common = 1, Rare = 1}, function() return 0.99 end) == "Rare"`, and `0 -> "Common"`.
- [ ] **Step 2: Run** `lune run tests/CraftConfig.spec.luau` from the repo root. Expected: FAIL (module missing).
- [ ] **Step 3: Implement** `src/ReplicatedStorage/CraftConfig.luau` with the interfaces above. Starter recipes (placeholders to rename, all `access = "known"` unless noted):
  - `RoughHelm` (Head, tier Scrap, 20 Scrap, ¥300, 60 s, weights Common 80 / Uncommon 20, `maxLevel` 20) and `RoughPlate` (Body, same numbers).
  - `ReinforcedHelm` (Head, tier Core, 15 Core, ¥2,000, 300 s, Uncommon 55 / Rare 45, `maxLevel` 50), `access = "learn"`, routes `{ {kind="buy", yen=5000} }`.
  - `PrismHelm` (Head, tier Essence, 5 PrismShard + 3 Essence, ¥50,000, 1,800 s, Epic 70 / Legendary 30, `maxLevel` 100), `access = "learn"`, routes `{ {kind="drop", blueprint="PrismHelmBlueprint"} }`.
  - `VigorCharm` (talisman `Vigor`, tier Core, 8 Core, ¥1,500, 120 s), `access = "learn"`, routes `{ {kind="quest", id="CraftIntro"}, {kind="faction", faction="Any", rank=2} }`.
  Verify the `faction` route fields against `FactionConfig` before using them (Task 3 reads them).
- [ ] **Step 4: Run** the spec again. Expected: all `ok`, exit code 0. Then `bash tests/run.sh` to confirm nothing else broke.
- [ ] **Step 5: Commit** `git add src/ReplicatedStorage/CraftConfig.luau tests/CraftConfig.spec.luau` and `git commit -m "Crafting: CraftConfig recipes and pure rules"`.

### Task 2: Crafting server module, remote and saving

**Files:**
- Create: `src/ServerScriptService/Crafting.luau`, `src/ServerScriptService/CraftServer.server.luau`
- Modify: `src/ServerScriptService/PlayerStats.luau` (TEXT_DEFAULTS around line 61, TEXT_LENGTHS around line 89)

**Interfaces:**
- Consumes: Task 1's `CraftConfig`; `Talismans.Grant(player, key): string?`; `Gear.Grant` (see Global Constraints); `DropConfig.Attribute(key)`; `TalismanConfig.Owned(ownedText)`.
- Produces: `Crafting.Start(player, id): (boolean, string?)`, `Crafting.Collect(player, index): (boolean, string?)`, `Crafting.Cancel(player, index): (boolean, string?)`, `Crafting.Learn(player, id, route): (boolean, string?)`; the `CraftAction` RemoteFunction: `InvokeServer("start"|"collect"|"cancel"|"learn", arg1, arg2) -> ok, why`.

- [ ] **Step 1: Register the saved texts** in `PlayerStats`: `PrintJobs = ""` and `RecipesKnown = ""` in `TEXT_DEFAULTS` (comments naming `CraftConfig`, `Crafting`), and `PrintJobs = CraftConfig.MaxSaveLength`, `RecipesKnown = CraftConfig.MaxSaveLength` in `TEXT_LENGTHS` (require `CraftConfig` next to the other config requires).
- [ ] **Step 2: Implement `Crafting.Start`** following `Talismans`/`Reforge` style: check data is loaded (attributes non-nil), the player is within `CraftConfig.Range` of a model tagged `CraftConfig.Tag` (copy the range check from `Reforge`/`ReforgeServer`), `CraftConfig.Start` accepts, `CanAfford` against `Mat_` attributes and yen, a talisman output is not already owned, then take all materials and yen and `SetAttribute(JobsAttribute, newText)` with a seed from `Random.new():NextInteger(1, 2^31-1)` and `workspace:GetServerTimeNow()`-independent `os.time()` for `now`/`finishAt`.
- [ ] **Step 3: Implement `Collect`**: job must be ready; talisman → `Talismans.Grant`, if it returns nil because already owned, refund the materials and clear the job; gear → `Gear.Grant` if the module exists (`script.Parent:FindFirstChild("Gear")`), else return `false, "Gear isn't available yet"` and leave the job; bag-full refusal from `Gear.Grant` returns `false, "Gear bag is full"` and leaves the job. On success remove the job.
- [ ] **Step 4: Implement `Cancel`** (`CraftConfig.Remove` on a not-ready job only, then add `CraftConfig.Refund` materials, clamped by `DropConfig.Fit`) and **`Learn`** (route `buy`: take the route's yen; `drop`: take 1 of `Mat_<blueprint>`; `quest`/`faction`: leave a clearly named stub `checkRoute` that Task 3 fills; spend only after `CraftConfig.Learn` succeeds).
- [ ] **Step 5: `CraftServer.server.luau`** creates the `CraftAction` RemoteFunction in `ReplicatedStorage` (by script, like `TalismanAction`), validates argument types, and keeps a per-player busy flag so a second call while one runs returns `false, "Busy"`.
- [ ] **Step 6: Compile check** with Lune's `luau.compile` on all three files (see memory: Lune path `C:\Users\Admin\tools\lune\lune.exe`; a one-line `lune run` script calling `luau.compile(fs.readFile(...))`). Expected: no errors.
- [ ] **Step 7: Commit** `git add src/ServerScriptService/Crafting.luau src/ServerScriptService/CraftServer.server.luau src/ServerScriptService/PlayerStats.luau` and `git commit -m "Crafting: server module, remote and saved jobs"`.
